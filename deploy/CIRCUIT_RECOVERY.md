# 熔断自主处置手册

## 2026-08-29 发件熔断记录

- 请求超时：集中发送正常需要超过15秒，执行器曾提前断开并误报告警；发件箱证明对应批次全部 `accepted`。现集中发送单独等待25分钟，任何超时都先以后续发件箱幂等状态为准，禁止直接重发。
- 库存衔接：跨批次草稿进入 `feedback` 后曾无法再次进入发送选择器，导致库存存在但数字不增长。现托管任务的未发送草稿可继续进入每日发送池，仍受收件人防重、每公司每日2位、统一账号容量和全局容量限制。
- 自然反馈：本小时集中记录11条 `hard_bounce` 和1条 `auto_reply`；硬退信目标均自动抑制并标记无效，发件箱 `sending=0`、`uncertain=0`。
- 恢复与结果：首次熔断通过 `RECOVER DELIVERY` 安全核查后继续；批次完成后的退信熔断保留冷却并自动恢复，但首页当日状态显示“当日任务已结束”。

## 自动处置矩阵

| 熔断 | 自主核查与处置 | 恢复条件 |
| --- | --- | --- |
| `hard_bounce` | 将目标永久抑制并标记无效，等待冷却 | 对应反馈存在、目标已隔离、无 `sending/uncertain` |
| `complaint` | 将目标永久抑制并标记退订，等待冷却 | 单次投诉且目标已隔离、无 `sending/uncertain`；24 小时内重复投诉转人工告警 |
| `rate_limit` / `provider_temporary` / `smtp_temporary` | 保持现有任务和草稿，不重试已接受邮件 | 冷却结束且无 `sending/uncertain` |
| 集中发送请求超时 | 不按客户端超时判断失败；读取幂等发件箱并由下一轮定时器续接未发送草稿 | 已接受记录不重发；无 `sending/uncertain` 后继续剩余草稿 |
| 库存存在但发件数字不增长 | 同时核对库存、`currentSendableCount`、任务阶段和每日额度；托管 `feedback` 任务的剩余草稿可跨批次续发 | 有剩余额度、未抑制、未重复且未超过公司/账号上限 |
| 网易 `frequent_operation` / `429` | 停止点击、保持浏览器会话、等待平台冷却 | 页面恢复正常后由托管定时器继续 |
| 验证码、登录、MFA、权限 | 停止自动操作并发送介入邮件 | 用户完成不可自动代办的验证后，定时器继续 |
| 页面结构、流水线输入异常 | 保留队列、产物和检查点并发送介入邮件 | 结构或输入核验通过后从原检查点恢复 |

所有恢复都保留运行态历史；已接受、`sending` 或 `uncertain` 邮件禁止自动重发。
当日发送额度已用完或单向循环已经没有待执行项时，首页必须显示“当日任务已结束”；仍在冷却的全局熔断只影响后续发送，并继续在运行控制和邮件安全状态中保留。
代码部署和定时健康巡检允许保留已开启的发送熔断：熔断代表发送被安全阻止，不代表应用不健康；健康门仍必须验证应用、运行态、告警配置和服务状态，部署不得擅自关闭熔断，且巡检失败必须正确传递非零状态。
